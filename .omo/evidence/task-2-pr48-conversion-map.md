# Todo 2: PR #48 to workflow v2 conversion map

This is the explicit source-to-target contract for the forward migration generated in Todo 3. Source models from migrations `0001`-`0004` remain historical; v2 source JSON defines the destination. Conversion must preserve audit history without inventing work assignments, opaque tokens, or readiness facts.

## Safe defaults

- A relationship that cannot be proved from PR #48 data remains nullable and retains its legacy identity in an explicit `legacy_*` field. In particular, attendance and day-level logs do not manufacture `work_id` or `work_assignment_id`.
- Legacy equipment is converted to `ownership_type=SHARED`, `owner_employee_id=NULL`, `status=BLOCKED`, with no `equipment_tag_tokens` row. An administrator must review/map the asset and issue a new random token; `equipment.nfc_tag_uid` is never hashed or reused as the opaque token.
- Legacy document review remains attached to the existing document as version 1. A `CONFIRMED` source remains confirmed; all other source values remain pending. No reviewer or review timestamp is fabricated.
- PR #48 approval is not a v2 readiness authority. It is retained only in the legacy attendance/approval tables for audit and is not copied to v2 preparation or gate decisions.
- `employee_health_profiles` and `work_restriction_rules` remain legacy records but are deprecated as readiness inputs; no health-derived v2 target rule is inferred.

## New v2-only identities and constraints

- `work_assignments`: retained `assignment_id` remains the primary key. Additive nullable `v2_work_id` plus `UNIQUE(v2_work_id,employee_id)` allows one worker on many v2 works while leaving unconverted legacy rows with `v2_work_id=NULL`.
- `equipment_check_events`: `UNIQUE(employee_id,idempotency_key)` stores request fingerprint, HTTP status, stable reason code, and exact response JSON for deterministic replay.
- `work_assignment_equipment`: `UNIQUE(work_assignment_id,equipment_id)` preserves accepted allocation history.
- `shared_equipment_claims`: `UNIQUE(equipment_id)` is the portable active-claim lock; a claim row exists only while the assignment is non-terminal. `STOPPED` retains it, while `COMPLETED` or `CANCELLED` releases it.
- `equipment_tag_tokens.tag_token_hash`: unique 64-character SHA-256 hash with issue/active/deactivation metadata.
- `gate_events.gate_event_id`: immutable append-only row identity. New request replay uses `UNIQUE(terminal_id,idempotency_key)`; no `updated_at` exists.
- `work_targets` permits either a container or cargo item target. The preparation layer must require at least one target and validate the discriminator before readiness; cross-column XOR is deliberately enforced in domain logic because the model-source migration generator's portable check support is intentionally narrow.
