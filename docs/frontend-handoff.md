# PortSyncAI 프론트 구현·인수인계 기준

## 1. 확정 실행 구조

| 사용자 | 실행 형태 | 입력 장치 | 역할 |
|---|---|---|---|
| 작업자 | `apps/front` Next.js 정적 UI를 Tauri 2로 패키징한 모바일 앱 | 휴대폰 NFC | 배정 작업 확인, 교육 적격성 확인, 지침 확인, 보호구 태깅, 게이트 준비 |
| 관리자 | `apps/admin` 반응형 웹 | 키보드·마우스 | 직원·조직, 문서·화물, MSDS 보호구 검수, 작업·팀 배정, 교육·작업중지, 게이트 이력 |
| 게이트 | 다음 실증까지 `apps/admin/gate-terminal` 태블릿 전체화면 | 사원증 NFC 리더 또는 데모 입력 | 사원증 식별 후 서버 PASS/BLOCK 판정 표시 |

작업자 앱과 게이트 단말의 NFC 역할은 섞지 않는다. 보호구는 작업자 휴대폰으로 읽고, 사원증은 게이트 리더로 읽는다.

## 2. 작업자 핵심 흐름

1. 로그인 후 당일 배정 작업을 선택한다.
2. 작업·화물에 필요한 법정교육 이수시간과 유효기간을 먼저 판정한다. 미충족이면 이후 단계를 열지 않는다.
3. 작업·화물·기상 조건에 맞는 당일 안전지침을 끝까지 확인하고 확인시각을 기록한다.
4. MSDS 8항과 작업유형으로 확정된 필수 보호구를 휴대폰 NFC로 읽는다.
5. 앱은 태그 토큰과 작업·보호구 카테고리를 서버에 보내고, 서버가 등록·사용중지·작업 적합성을 판정한다.
6. 작업 배정, 교육, 지침, 보호구, 작업중지 상태가 모두 정상일 때만 게이트 준비를 기록한다.
7. 현장 게이트에서 사원증을 읽으면 서버가 조건을 다시 판정하고 PASS/BLOCK과 구체 사유를 반환한다.

예외 승인은 교육 미이수나 보호구 미확인을 면제하지 않는다. 파손 장비 교체, 대체 보호구 확인, 개인 보호구 등록처럼 관리자 확인이 필요한 경우에만 요청하며 승인 전에는 통과를 제한한다.

## 3. 보호구 NFC 계약

작업자 앱이 API에 보낼 최소 데이터는 다음과 같다.

```json
{
  "assignmentId": "WB-260823-03",
  "equipmentCategory": "내화학 장갑",
  "tagToken": "04A1B2C3D4E5F6",
  "scannedAt": "2026-08-23T07:31:22.000Z",
  "device": {
    "channel": "phone-nfc",
    "platform": "tauri-mobile"
  }
}
```

- NFC 원문에서 태그 식별 토큰만 사용하며 불필요한 NDEF 개인정보는 수집하지 않는다.
- 태그 토큰만으로 안전조건 충족을 확정하지 않는다. 서버가 장비 등록, 카테고리, 사용중지, 작업 적합성을 확인한다.
- 실제 착용을 증명한다고 표현하지 않고 작업 전 준비·수령 확인으로 정의한다.
- 동일 토큰 재시도는 멱등하게 처리하고 중복 태깅으로 여러 사용이력이 생성되지 않게 한다.

## 4. 로컬 실행

```bash
# 웹 미리보기
bun install
bun --filter front dev
bun --filter admin dev

# 작업자 앱 정적 산출물 확인
cd apps/front
bun run build:tauri

# Android 최초 설정 및 실행
bun run tauri:android:init
bun run tauri:android:dev
```

Android Studio, Android SDK, JDK와 Rust Android target 설치가 필요하다. `NEXT_PUBLIC_API_BASE_URL`은 휴대폰에서 접근 가능한 개발 서버 주소로 지정한다. 실제 휴대폰에서 `localhost`는 PC가 아니라 휴대폰 자신을 가리키므로 사용할 수 없다.

## 5. 제출 전 남은 확인

- Android NFC 지원 실기기에서 보호구 태그 읽기 성공·취소·NFC 꺼짐·미지원 기기 상태를 확인한다.
- `POST /equipment-checks`와 작업자 앱 payload를 연결하고 정상·미등록·사용중지·카테고리 불일치 응답을 화면에 반영한다.
- 태블릿을 가로 전체화면으로 두고 사원증 정상·미등록·교육 미충족·보호구 미확인·작업중지 차단을 시연한다.
- Proxmox LXC 배포 주소와 TLS 인증서를 확정하고 모바일·태블릿에서 접근 가능한지 확인한다.
- 제출용 화면 캡처와 시연 데이터의 날짜·작업코드·컨테이너 번호를 개발보고서와 맞춘다.
